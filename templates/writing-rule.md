# writing-rule.md

Writing style for every doc an autobuild skill produces in this project. Edit it to suit the project.

## Prose

- Write for a capable teammate who was not in the conversation.
- Keep sentences active and short: 20 words a sentence, 2 sentences a line.
- Use plain, common words. State a rule once.
- Put one idea that spans several lines in a list instead.
- Write an item with more than two fields as one block, not a single-line row.

## Facts

- Keep researched facts, user decisions, and build choices apart. Name which one each line is.
- Name an uncertainty as one. Never turn a guess into a requirement.
- Cite the source of any outside claim a decision rests on.
- Write the real content every time. Never write "similar to X" or "TBD."
- Do not invent product limitations. Write a limit only when the user stated it or research proved it, and name its scope.
- When trimming, cut a qualifier or filler first, never the fact the sentence exists to state.

## Vocabulary

| Shorthand | Plain term |
|---|---|
| item | The only word for a backlog entry, not "ticket." |
| product | The only word for the thing being built, not "the app." |
