# writing-rule.md

Writing style for every doc an autobuild skill produces in this project.

## Prose

- Write in ASD-STE100. Keep sentences active and short.
- Keep each sentence to 20 words. Keep each line to 2 sentences.
- State a rule once. Skip the reasons behind it.
- Use plain, common words.
- One idea forced across several lines belongs in a list instead.
- An item with more than two fields is one block per item, not a single-line row.
- Give every list a hard budget. Keep it short and specific.

## Docs

- A produced doc never says "similar to X" or "TBD." It repeats the real content every time.
- A produced doc records positive facts only — what a thing is, does, or will do. It never states an exclusion or a boundary: "never X," "no X," "out of scope."
- A negating word can still state a capability, not a boundary — "nothing to install," "never fails" stay as written.
- When trimming is genuinely needed, cut a qualifier or filler first, never a fact the sentence exists to state.

## Vocabulary

| Shorthand | Plain term |
|---|---|
| item | The only word for a backlog entry, not "ticket." |
| product | The only word for the thing being built, not "the app." |
